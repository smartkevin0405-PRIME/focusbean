# 집중콩 0.13-beta · 삼성 인터넷 웹 쇼츠 감지 보강

2026-11-02 · versionCode 13 / versionName 0.13-beta · minSdk 26 / targetSdk 35

## 원인과 변경

실기기 사진에서는 유튜브 웹 쇼츠가 재생되고 주소창은 `m.youtube.com`만 표시된다. 0.12는 도메인만으로 일반 유튜브까지 차단하지 않도록 수정했지만, URL 경로·쇼츠 클릭 메타데이터가 노출되지 않는 경우 보조 플레이어 감지가 없었다. 기존 BrowserInspector는 문서 루트의 URL을 읽고 자식 탐색을 중단하여 웹 플레이어의 버튼을 검사하지 않았다. 사진만으로 접근성 노드에 실제 노출되는 문구·좌표·ID나 서비스 연결 상태까지 확정할 수는 없다.

0.13은 도메인만 읽히는 유튜브 화면에서 웹 문서 내부를 최대 600개 노드까지 추가로 검사한다. 세로 화면 오른쪽에 좋아요·댓글·공유 버튼이 일정 간격을 두고 세로로 배치되고, 아래쪽에 구독/채널 핸들 신호가 함께 있을 때 쇼츠 플레이어로 판정한다. 후보 플레이어 HTML ID가 넓게 표시된 경우에는 서로 다른 오른쪽 버튼 2개를 보조 증거로 사용한다. 웹 문서 밖의 브라우저 기본 UI는 판정에 쓰지 않는다. 여러 웹 문서의 신호를 합치지 않는다.

현재 URL이 명시적인 일반 영상 경로이거나 웹 문서의 유튜브 홈으로 확인되면 이 보조 판정을 실행하지 않는다. `#shorts`라는 영상 제목·추천 링크·Shorts 탭 하나만으로는 차단하지 않는다. 주소 입력 중·숨겨진 노드·편집 노드도 제외한다. 일반 유튜브 도메인 전체 차단은 다시 넣지 않았다.

쇼츠 플레이어로 판정하면 기존 안전 헬퍼를 통해 활성 브라우저에만 BACK을 요청한다. 850ms 후에도 동일 창에서 쇼츠 URL/플레이어 신호가 확인될 때만 HOME을 요청한다. 집중콩·전화·SystemUI 보호와 게임/PiP·설정 가드·분 단위 입력·통계·XP는 변경하지 않았다. 새 네트워크 통신·권한은 없다. 화면의 문구와 좌표는 메모리에서만 검사하며 URL·영상 제목·채널 핸들을 진단에 남기지 않는다.

## 실기기 확인 필요

상수는 `DeviceConstants.java`의 WEB_PLAYER_IDS, WEB_LIKE_LABELS, WEB_DISLIKE_LABELS, WEB_COMMENT_LABELS, WEB_SHARE_LABELS, WEB_SUBSCRIBE_LABELS다. 후보 ID는 shorts-player / reel-player, 문구는 좋아요·댓글·공유·구독 및 영어 표현이다. 사진은 보이는 배치만 보여 주며 삼성 인터넷이 접근성에 같은 문구를 제공하는지는 미확인이다. 기기가 웹 자식·버튼 설명·좌표를 공개하지 않으면 계속 감지가 누락될 수 있다. 이 경우 외부 삼성 인터넷에서 완전 차단을 보장하지 않는다.

계속 재생되면 접근성 연결 카드의 **진단 복사 · 주소·제목 제외** 결과가 필요하다. 특히 `서비스 연결됨`, `웹 노드`, `오른쪽 동작`, `복구한 오류`를 확인한다. 화면 ID 수집은 기존 30초 예약으로 수행한다. 실기기 확인 전에는 성공으로 단정하지 않는다.
