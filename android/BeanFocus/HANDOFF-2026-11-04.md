## 2차에서 확인한 사실 (Chromium 소스)

출처는 `chromium/chromium` main의 다음 파일이다.

- `WebContentsAccessibilityImpl.java`
- `AccessibilityNodeInfoBuilder.java`
- `browser_accessibility_android.cc`
- `web_contents_accessibility_base.cc`
- `AccessibilityStateDelegateImpl.java`

1. **접근성 노드에는 문서 주소(`url` extra)가 들어가지 않는다.**
   - `EXTRAS_KEY_URL`은 `onProvideVirtualStructure`(Assist·자동완성용 ViewStructure)에서만 쓰인다.
   - `targetUrl`은 링크·이미지·비디오에만 붙는다.
   - 따라서 0.13~0.15 1차의 "웹 문서 루트 URL" 경로는 실제 삼성 인터넷에서 거의 동작하지 않았을 가능성이 높다. 코드는 혹시 제공하는 빌드를 위해 남겨 두었다.
2. 실제로 쓸 수 있는 신호는 다음과 같다.
   - 주소창 텍스트. 삼성은 보통 도메인만 보여주고, 스크롤하면 주소창이 숨겨진다.
   - 링크·비디오의 `targetUrl`. 절대 주소이고, 비디오는 `blob:https://m.youtube.com/...` 형태다.
   - HTML `id`(viewIdResourceName)
   - 버튼 이름과 배치
3. 이 서비스는 `TYPE_VIEW_SCROLLED`를 요청한다.
   - 그래서 Chromium은 이 서비스를 "complex service"로 보고 `kAXModeComplete`를 쓴다.
   - 축소 AXMode는 원인이 아니다. 단, 이는 현재 Chromium 기준이고 삼성 버전은 다를 수 있다.

## 2차 수정 내용

1. **루트를 잠깐 못 읽을 때(인계 1번)**
   - `BrowserScanPolicy.missingRootDelay`로 3초 탐색 마감 안에서 150ms 간격으로 재시도한다.
   - 앞에 다른 앱이나 다른 창이 보이면 즉시 종료한다(`FocusService.retryMissingRoot`, `frontMayBe`).
2. **창 ID -1(인계 2번)**
   - `navigation(...,-1)`은 같은 브라우저의 현재 범위를 유지한다. 그 뒤 처음 스캔한 실제 창에 결합되고, 탐색 마감도 그대로 유지된다.
   - 다른 실제 창에 결합되면 그 창은 새 검사 예산을 받는다.
   - 실제 ID를 확보한 뒤의 BACK/HOME 창 검사 조건은 그대로다.
3. **주소창이 숨겨졌거나 도메인만 보일 때**
   - 창마다 호스트 분류(유튜브 1, 다른 사이트 -1, 미확인 0)만 기억한다. 주소는 저장하지 않는다.
   - 주소가 안 읽히면 다음 경우에만 웹 문서를 검사한다.
     - 이 창이 마지막으로 유튜브였을 때: 화면 링크가 다른 사이트를 가리키지 않는 한 유튜브로 본다.
     - 호스트가 미확인일 때: 화면 안 링크·비디오의 출처가 유튜브여야 유튜브로 본다.
   - 이렇게 유튜브로 확인된 경우에만 쇼츠 버튼 배치를 차단 근거로 쓴다.
   - 다른 사이트로 기억된 창은 검사하지 않는다.
   - 화면 밖 노드와 iframe 링크는 세지 않는다.
   - 버튼 배치만으로는 차단하지 않는다. 진단에는 링크 개수만 표시한다.
4. **네이티브 유튜브(인계 6번)**
   - 이벤트 스로틀(`youtubeEventDue`)을 루트·창 조회보다 먼저 확인한다.
   - 쇼츠 BACK과 이어지는 HOME에 캡처한 창 ID를 전달한다.
5. **삼성 인터넷 콘텐츠 차단기 추가** (Samsung Content Blocker API 1.0)
   - Manifest에 `com.samsung.android.sbrowser.contentBlocker.interfaceVersion=API_1.0`를 넣었다.
   - `ShortsFilterProvider`를 추가했다. authority는 `app.bean.focus.contentBlocker.contentProvider`이고, 외부 공개지만 읽기 전용이다.
   - 규칙(`ShortsFilterRules`)은 `||youtube.com/shorts`, `||youtube.com/youtubei/v1/reel/`, 그리고 쇼츠 선반 요소 숨김 3개뿐이다.
     - `reel/reel_item_watch`와 `reel/reel_watch_sequence`는 쇼츠 전용 InnerTube 엔드포인트다(YouTube.js 소스로 확인).
     - `/watch`, `youtubei/v1/player`, `youtubei/v1/next`, 검색, 채널 페이지는 막지 않는다. 테스트로 확인했다.
   - 쇼츠 차단이 꺼져 있으면 쇼츠 규칙을 뺀다. 3차부터는 아무것도 막지 않는 자리표시 규칙(`||beanfocus.invalid^`) 하나를 남긴다.
   - 상태가 바뀌면(스위치, 잠금 시작·종료, 앱 첫 실행) 삼성 인터넷 패키지에 `ACTION_UPDATE`를 명시적으로 보낸다. AdGuard Content Blocker와 같은 방식이다.
   - 메인 화면에 "삼성 인터넷 쇼츠 차단기" 카드를 추가했다. 광고 차단기 설정 열기 버튼과 상태가 있다.
   - '진단 복사'에 삼성 인터넷이 목록을 언제 가져갔는지 시각만 표시한다.
   - 사용자가 삼성 인터넷 → 광고 차단기에서 집중콩을 직접 켜야 동작한다.

## 3차 (2026-11-09): 광고 차단기 목록에서 집중콩이 사라진 문제

- 실기기 보고: 삼성 인터넷이 목록을 한 번 가져간 뒤(진단 "4786분 전에 가져감"), 광고 차단기 목록에서 집중콩이 사라졌다.
- AdGuard Content Blocker 소스와 비교한 차이 두 가지를 고쳤다.
  - 권한: AdGuard·Adblock Plus는 `com.samsung.android.sbrowser.permission.CONTENTBLOCKER`를 선언한다. 집중콩에는 없었다. Manifest에 추가했다.
  - 재알림: AdGuard는 삼성 인터넷이 업데이트되면 `ACTION_UPDATE`를 다시 보낸다. 집중콩은 프로세스당 상태가 바뀔 때만 보냈다.
- 이제 `ACTION_UPDATE`를 다시 보내는 경우:
  - 삼성 인터넷 설치·업데이트(`FocusService`의 런타임 `PACKAGE_ADDED` 수신기)
  - 마지막 알림 후 6시간
  - '광고 차단기 설정 열기' 버튼을 누를 때
- 진단에 "마지막 알림 N분 전"을 함께 표시한다. 알림 뒤에도 가져간 시각이 바뀌지 않으면 삼성 인터넷 쪽에서 꺼졌거나 빠진 것이다.
- 삼성 개발자 문서(developer.samsung.com)는 이 세션 네트워크에서 열 수 없었다. 권한이 목록 표시 조건인지는 문서로 확인하지 못했다. 실기기에서 목록 재등장을 확인해야 한다.
- 사용자 확인(11-10): 목록에 있던 3일 전에는 삼성 인터넷에서 쇼츠가 실제로 막혔다. 규칙은 동작한다. 문제는 목록에서 빠지는 것이다.
- 쇼츠 차단이 꺼지면 규칙 0개 목록을 줬다. 삼성 인터넷이 빈 차단기를 빼는지는 미확인이다. 그래도 빈 목록을 주지 않게 바꿨다. 꺼짐 상태에서는 예약 도메인 `.invalid`의 자리표시 규칙 하나만 준다.
- 같은 보고에서 접근성 경로도 실패했다: "UI 161 · 문서 0 · 플레이어 0", "웹 루트 없음". 0.13 보고(웹 노드 0)와 같다.
  - Chromium main 기준으로는 이 서비스 설정(`TYPE_VIEW_SCROLLED` 요청)이 웹 트리를 받아야 한다. 그래서 원인을 셋으로 나눴다.
    1. 삼성 인터넷이 웹 트리를 주지 않는다.
    2. 웹 노드는 있지만 클래스·역할이 달라 웹 루트로 못 알아본다.
    3. Chromium은 첫 요청에 빈 결과를 주고 비동기로 연결한다. 서비스 캐시에 빈 페이지 뷰가 남는다.
  - `BrowserInspector`가 웹 루트를 못 찾으면 가장 큰 빈 뷰를 한 번 `refresh()`(캐시 우회)한다. WebView로 바뀌면 그대로 검사한다(3번 대응).
  - 진단에 "웹 영역 진단" 줄을 추가했다. 내용은 Chromium 역할 노드 수, `android.view.View` 수, 숨은 웹 루트 수, 가장 큰 빈 뷰의 클래스와 새로고침 후 자식 수다. 텍스트·주소는 넣지 않는다.
  - 판독: 역할 0·View 0·빈 영역 자식 0이면 1번이다. 역할이나 View가 많으면 2번이다. "웹 루트 확보"가 뜨면 3번이었다.
  - 테스트: `tests/BrowserEmptyPageTest.java`.

## 남은 결함과 검토 사항 (우선순위 순)

1. **실기기 확인이 최우선이다.**
   - 삼성 인터넷 광고 차단기 목록에 집중콩이 뜨는지 확인한다.
   - 켠 뒤 '진단 복사'에 "삼성 인터넷이 N분 전에 가져감"이 나오는지 확인한다.
   - 쇼츠가 실제로 막히는지 확인한다: 홈 썸네일(SPA 이동), 쇼츠 탭, `/shorts/` 직접 입력, 공유 링크.
2. **규칙 지원 범위는 미확인이다.**
   - `||youtube.com/shorts`가 메인 프레임 문서 로드까지 막는지는 삼성 엔진에 달려 있다.
   - 요소 숨김(`##`) 지원 여부도 마찬가지다.
   - SPA 이동은 `reel/` API 차단으로 막히는 것을 기대한다.
   - 규칙을 넓힐 때 유튜브 도메인 전체나 `$document` 전체 차단을 넣지 말 것.
3. **잠금 중 해제 경로가 남아 있다.** 삼성 인터넷 설정에서 차단기를 끄는 것은 막지 못한다. 설정 가드 대상이 아니다. 필요하면 별도 범위로 검토한다.
4. **Chromium 내부 캐시(1차 3번)는 그대로다.** 일반 홈·영상까지 차단하는 방향으로 바꾸지 말 것.
5. **버튼 판별은 합성 노드 기반이다.** 이름·배치·`shorts-player` ID는 실제 화면 덤프로 확인해야 한다.
6. **추가 비용은 측정하지 않았다.**
   - 주소창이 숨겨지고 호스트가 미확인인 페이지에서 최대 600노드 검사가 추가된다. 간격은 평소 5초, 탐색 직후 500ms다.
   - 1차의 탐색 직후 재검사와 루트 refresh 비용도 아직 측정하지 않았다.
7. 네이티브 유튜브는 잠금 중 앱 전체 차단 정책을 유지한다. 잠금 밖 쇼츠 감지는 플레이어 ID 3개에 의존한다.

## 실제 기기에서 확인할 최소 시나리오

1. 기본 정보를 확인한다: 삼성 인터넷 버전, 기기·One UI 버전, 설치된 집중콩 버전, 서비스 연결 진단.
2. 콘텐츠 차단기를 확인한다.
   - 메인 → "삼성 인터넷 쇼츠 차단기" → 설정 열기 → 집중콩을 켠다.
   - 상태 줄과 '진단 복사'를 확인한다.
3. 차단기를 켠 상태와 끈 상태에서 각각 확인한다.
   - 홈 쇼츠 썸네일, 쇼츠 탭, 쇼츠 URL 직접 입력, 일반 영상에서 쇼츠로 이동
   - 일반 `/watch`·홈·검색 결과·채널 페이지가 정상인지
   - 쇼츠 차단 스위치를 끄면 쇼츠 규칙이 빠지는지
4. 접근성 경로를 확인한다(차단기를 끈 상태).
   - 주소창이 보일 때와 숨겨졌을 때(쇼츠 스와이프 후) 감지되는지
   - 진단의 "화면 링크 유튜브 n / 기타 m"과 "웹 플레이어" 줄
   - 주소 입력 중에는 자동 이동이 없어야 한다.
5. 그 밖의 상황을 확인한다: 페이지 준비가 느린 경우, 새 탭 전환, 앱 전환, 화면 끔, 뒤로 이동.
6. 노드가 없거나 신호가 부족하면 진단을 먼저 확보한다.
   - `화면 view ID 수집 예약 · 30초`는 텍스트·URL·extras 없이 ID만 모은다.
   - 개인 페이지나 영상 내용 덤프는 무단으로 저장하거나 업로드하지 않는다.

- 키 위치나 암호는 이번 세션에서도 읽거나 출력하지 않았다. 새 키도 만들지 않았다. 원래 서명키가 이 작업 공간에 준비됐다고 가정하지 말 것.

- 기존 인증서 SHA-256(공개 식별 정보): `5e7325b0fbb0af5df2c80c300f0ac8d7e6e1ccd1d23bae0f8b6e2baec4b748f4`
- 공개하기 전에 할 일:
  - 최종 소스 커밋을 정한다.
  - `.github/scripts/verify_apk.py`로 실제 APK를 독립 검증한다. 대상은 ID, 버전, SDK, 서명, SHA-256, sourceCommit이다.
  - `release/BeanFocus.apk.b64`와 `release/release.json`을 함께 맞춘다.
  - publish workflow가 배포를 일으키므로 미완성 APK로 갱신하지 말 것.
- 기존 앱 삭제나 데이터 초기화 없이 업데이트한다. 설치 시험은 집중 잠금이 끝난 상태에서 진행한다.
