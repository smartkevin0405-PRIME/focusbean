## 확인한 결함과 적용한 수정

1. **클릭 확인의 5초 공백**: 이전에 플레이어를 검사한 직후 쇼츠를 누르면 450ms 후 확인도 5초 플레이어 쿨다운에 막혔다. 클릭 확인은 일반 500ms 검사 예산도 우회했다.
   - `BrowserScanPolicy`에 3초 탐색 기간을 추가했다. 클릭·창 상태 변경·주소창의 텍스트 변경만 이 기간을 시작한다. 이 기간에는 플레이어를 최소 500ms 간격으로 검사하고 이후에는 기존 5초 간격을 사용한다.
   - `FocusService.queueClickedShorts`는 이동 명령 대신 공유 검사 예약만 한다. 첫 예약은 최소 450ms이며 이벤트/주기 검사가 모두 같은 500ms 예산을 사용한다. 늦게 생성되는 플레이어도 3초 안에서 재확인한다.
   - 일반 페이지 본문 변경·스크롤·재생 업데이트는 기간을 연장하지 않는다. 주소 편집 또는 BACK 요청 시 탐색 기간을 끝낸다.
2. **주소창이 숨겨진 경우**: 문서 메타데이터가 `https://m.youtube.com`만 제공하면 기존에는 현재 URL에 반영되지 않아 플레이어 검사를 시작하지 못했다. 이제 이 문서 도메인으로 유튜브 문맥을 확인한다. 현재 유튜브 문서보다 오래된 다른 사이트 주소창을 우선하던 경우도 고쳤다.
3. **중첩 문서 루트 누락**: 자원 ID 없는 네이티브 래퍼와 도메인만 가진 중첩 WebView를 지나 실제 rootWebArea를 찾도록 보완했다. 네이티브 UI 180개, 문서 셸 24개/깊이 4, 문서 갱신 최대 4회, 플레이어 600개 상한을 유지한다.
4. **페이지 내부 전환 후 오래된 주소**: 문서 루트만 제한적으로 `refresh()`한다. 3초 이동 확인 중 또는 BACK 이후 재확인 시, 현재 화면의 쇼츠 플레이어 ID와 조작 버튼이 함께 확인되면 이전 홈/일반 영상 주소를 보완할 수 있다.
   - `BrowserInspector.read(root, pkg, allowPlayerFallback, navigationHint)`를 추가했다. 이전 2/3인자 호출은 navigationHint=false다.
   - 기존에 홈/일반 영상 경로가 확인된 경우 버튼 배치만으로는 차단하지 않는다. 알려진 플레이어 ID와 버튼 조합을 요구한다.
   - 이 예외로 playerShorts가 확인되면 confirmedHome()은 false여서 공통 차단 정책으로 이어진다.
5. **오래되거나 다른 화면의 증거**: Chromium offscreen 노드, iframe/다른 문서의 조작 버튼, 갱신 실패 문서를 제외한다. 갱신 실패한 하위 문서를 다시 플레이어 검사에서 읽는 경로도 제외했다.
6. 자동 이동 전 활성 패키지·창 ID·현재 쇼츠 증거를 확인하는 기존 보호를 유지한다. 도메인만 확인되거나 링크를 눌렀다는 사실만으로 유튜브 전체를 막지 않는다. URL/영상 제목을 진단에 저장하지 않는다.

## 남은 결함/검토 사항 (다음 세션 우선순위)

1. **전환 중 일시적으로 루트가 없으면 재시도가 끝남**: `FocusService.browserCheck`에서 `activeRoot(p, window)==null`이면 `browserBudget.endNavigation()`하고 반환한다. 페이지/접근성 제공자 준비 중 잠깐 루트가 없을 때 3초 재시도를 잃을 수 있다. 명확한 다른 앱/창 이동은 취소하되, 일시적 읽기 실패는 남은 마감 안에서 제한적으로 재시도하는 방안을 구현·검증할 것. 현재 파일에는 이 수정이 아직 없다.
2. **이벤트 창 ID -1**: `navigation(...,-1)` 후 실제 root window로 `scanned()`하면 scope가 바뀌면서 탐색 기간이 사라진다. 최초 일치 활성 창에 범위를 결합하는 방법 또는 명시적으로 이 경우를 처리하는 방법이 필요하다. 실제 ID가 확보된 뒤 이동 명령의 정확한 창 검사 조건은 유지할 것.
3. **Chromium 내부 URL 캐시**: Android `refresh()`가 브라우저 내부 캐시까지 갱신한다고 보장할 수 없다. 현재 공식 Chromium 구현의 cached node update는 좌표 위주다. 강한 플레이어 ID가 노출되지 않는 삼성 환경에서는 이전 홈 URL+실제 쇼츠 상태를 놓칠 수 있다. 무작정 일반 홈/영상 차단으로 바꾸지 말 것.
4. 플레이어 ID와 버튼 검출은 아직 합성 노드 기반이다. 실제 삼성 화면 덤프/앱 진단으로 ID·계층·extras·좌표 노출을 확인해야 한다. viewport 내 플레이어 ID+버튼 조합도 화면 구조 휴리스틱이며 완전한 재생 증명이 아니다.
5. **추가 비용 미측정**: 이동 직후 최대 3초의 더 잦은 보조 탐색과 루트 refresh가 추가된다. 실제 페이지 로딩 개선/악화를 확인하지 않았다. 진단의 검사 소요 시간은 페이지 로딩 시간이 아니다.
6. 네이티브 YouTube는 이번 주 대상이 아니다. 잠금 중 전체 앱 차단 정책을 유지했다. 검토에서 네이티브 이벤트의 root/windows 조회가 스로틀 전에 실행되고, 네이티브 Shorts 이동 시 캡처한 창 ID를 globalActionFor에 전달하지 않는 점이 발견됐으나 수정하지 않았다. 삼성 웹 검증 후 별도 범위로 검토할 것.
