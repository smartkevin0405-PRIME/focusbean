# 집중콩 0.14 베타 소스

2026-11-03 · Android 8 이상(API 26), target API 35. 개인용 디지털 디톡스 앱. 게임 차단, 웹 쇼츠 차단, 집중 잠금, 프라임콩 성장, 사용 통계, XP 수식 선택을 포함한다.

0.14 소스는 문서 URL 수집, 검사 합치기 및 추측에 의한 뒤로 이동을 수정한다.
현재 변경과 검증 결과는 [REPORT-0.14.md](REPORT-0.14.md), 빌드는 [BUILDING.md](BUILDING.md)를 따른다.
GitHub 최신 배포 APK는 아직 0.13이다. 0.14 서명/게시 및 실기기 확인은 별도다.
삼성 인터넷이 경로와 웹 노드를 모두 제공하지 않는 경우 쇼츠 구분은 여전히 불가능하다.

## 설치·업데이트

기존 앱과 앱 ID(`app.bean.focus`)와 서명키가 같아 설정과 성장 기록을 유지하며 업데이트할 수 있다.

```powershell
.\adb.exe install -r "$env:USERPROFILE\Downloads\BeanFocus-0.13-beta.apk"
```

폰에서 게임을 선택하고 Android 접근성 설정의 집중콩 서비스를 직접 켠다. 통계 화면의 `사용정보 권한`은 게임의 Android 앱 사용 기록을 가져올 때 필요하다. 이 권한은 설치나 ADB만으로 자동 허용되지 않는다. Family Link·기기 정책이 허용하지 않는 설정은 변경·우회하지 않는다.

## 차단과 잠금

- 선택한 게임은 잠금 여부와 관계없이 차단이 켜져 있으면 HOME을 요청한다. 집중 잠금 중에는 Android `CATEGORY_GAME` 또는 구형 `FLAG_IS_GAME` 분류의 앱도 자동 차단한다. 새 설치·변경 방송과 30초 브라우저 목록 재검색을 사용하고 2초 점검에서도 앞에 나온 게임을 확인한다. 분류가 없는 게임은 직접 선택해야 한다.
- HOME 뒤에도 팝업·분할 게임 창이 남으면 노출된 게임 영역에 `TYPE_ACCESSIBILITY_OVERLAY` 가림막을 표시한다. 더 위에 있는 다른 앱·시스템 창의 사각형은 제외하고, 설정·집중콩 화면·화면 잠금·서비스 해제 시 제거한다. 게임 프로세스나 소리까지 중단하는 기능은 아니며 실제 삼성 멀티윈도 호환성은 미검증이다.
- 외부 브라우저의 알려진 주소창 ID를 먼저 직접 조회하고 text와 contentDescription 중 경로가 확인되는 값을 우선한다. 보조 탐색에서는 웹 문서 루트의 현재 URL 메타데이터도 확인하며, 추천 링크를 현재 URL로 취급하지 않는다. `/shorts`가 확인되면 BACK 요청 후 850ms 뒤 같은 앱·창을 재확인한다. 쇼츠 경로가 여전히 확인되는 경우에만 HOME을 요청한다. OS가 요청을 수락한 횟수는 차단 성공 횟수와 구분한다.
- `TYPE_VIEW_CLICKED`의 클릭 노드 및 최대 8개 조상에서 Chromium `AccessibilityNodeInfo.targetUrl`을 읽는다. 쇼츠 링크 또는 유튜브 문맥의 `shorts-tab` 클릭을 감지하면 450ms 기다린 뒤 같은 패키지·창에서 BACK을 요청한다. 850ms 후에도 쇼츠 경로가 확인되면 HOME을 요청한다. 도메인만 보이거나 경로 확인이 안 된다는 이유로 일반 유튜브를 차단하지 않는다. 실제 링크 정보 노출 여부는 브라우저마다 다르며 앱 내부·커스텀 탭의 감지 누락 가능성이 남는다.
- `잠금 중 미지원 브라우저 제한` 옵션은 잠금 전에 바꿀 수 있다. 쇼츠 차단과 집중 잠금이 함께 켜진 동안 검색으로 발견한 미지원 브라우저를 HOME으로 보낸다. 삼성 인터넷 등 지원 브라우저의 도메인만 확인된 유튜브는 허용한다. URL 경로와 쇼츠 클릭 메타데이터를 모두 얻지 못하면 쇼츠 감지가 누락될 수 있다.
- 내장 WebView는 HTTPS 유튜브 주소만 열고 쇼츠 이동·링크·목록을 차단한다. Google 로그인은 지원하지 않는다. 일반 영상은 강의·여가 모두 허용한다. 페이지 내부 전환도 검사하지만 YouTube UI 변경이나 짧은 초기 노출을 완전히 차단한다고 보장하지 않는다.
- 1~180분 집중 잠금을 분 단위로 직접 입력할 수 있다. 잠금 중에는 전체 차단·쇼츠 스위치와 게임 목록을 변경할 수 없다.
- 조기 해제를 요청하면 10분 뒤 직접 `설정 잠금 해제`를 눌러야 한다. 앱 화면을 닫아도 대기는 계속된다. 요청을 취소하면 다음 요청은 다시 10분부터 시작한다.
- 잠금이 풀려도 기존 차단은 유지된다. 시간 계산은 같은 부팅 중에는 elapsedRealtime 기준이다. 재부팅 이후에는 저장된 실제 시각으로 복원하므로 재부팅과 시각 조작을 함께 하는 우회를 막는 기능은 아니다.
- 0.8의 선택한 설정 가드는 잠금 중 보호 앱의 해제·삭제 관련 화면에서 BACK을 요청한다. OS의 삭제 권한을 없애지 않으며 서비스 중단·UI 변경·안전 모드에서의 해제를 완전히 막지 못한다. 전화·긴급 통화는 가드 대상이 아니다. 실제 잠금 중 설정 가드 대상은 REPORT-0.10.md를 따른다.

## 처음 보는 채널 분류

내장 브라우저의 `/watch` 영상에서 현재 영상 ID와 일치하는 player response 또는 채널 소유자 DOM을 이용해 채널을 찾는다. 두 번의 연속 관측으로 채널이 안정적으로 확인되면 처음 본 채널에 대해 `강의 / 여가 / 미분류로 두기`를 묻는다. 질문 중에는 영상을 멈추고 시간 적립도 멈춘다. 답한 뒤 재생 버튼을 눌러야 한다.

채널 ID/핸들 별칭을 연결할 수 있는 경우 동일한 분류를 재사용한다. 외부 브라우저나 채널 정보 확인 실패는 임의로 분류하지 않고 미분류로 기록한다. 상단 `채널`에서 분류를 바꿀 수 있으며 변경은 이후의 관측에 적용한다. 분류하지 않은 채널은 미분류로 저장해 반복 질문하지 않는다. 채널 이름이 같다는 이유만으로 서로 다른 채널을 합치지 않는다.

이 기능은 채널 단위의 사용자 분류이며 개별 영상 내용의 자동 판별기가 아니다. 유튜브의 DOM/메타데이터 변경에 따른 실제 호환성 검증이 필요하다.

## 시간 관측소

- 오늘 누적, 최근 7일과 직전 7일, 최근 30일과 직전 30일을 전환한다. 7·30일 비교는 진행 중인 오늘을 제외한 완료된 날짜끼리 비교하며 실제 날짜를 표시한다. 오늘은 누적만 표시한다.
- 웹 강의·여가·쇼츠·미분류 시간, 선택 게임 시간, 차단 시도, 차단 연결 유지, 획득 XP를 표시한다.
- 일별 누적 막대·이전 기간 점선, 지표 선택, 날짜 탭 상세, 웹 시간대 분포, 게임·채널별 순위, 날짜별 상세표를 제공한다.
- 웹 시간은 실제 재생 시간이 아니라 지원 화면에서 관측한 이용 시간이다. 홈·검색은 미분류로 포함될 수 있다. 외부 브라우저 주소창을 확인하지 못한 동안이나 서비스 중단 구간은 복원하지 않는다.
- 웹 비교는 양쪽 기간의 모든 날짜에 관측 기록이 있고 서비스 관측 시간 비율이 0.8~1.25이며, 각각 미분류 비중이 10% 이하일 때만 표시한다. 이 기준도 모든 이용을 측정했다는 보장은 아니다. 값은 관측 기준의 감소량이며 차단의 인과적 효과·확정 절약 시간으로 표현하지 않는다.
- 게임의 과거 기록은 사용정보 접근 권한을 받아 Android `INTERVAL_DAILY` 앱 사용 기록에서 가져온다. 보관 범위는 기기에 따라 다르며 없는 날은 0으로 채우지 않는다. 게임별 조회 범위는 Android의 일 단위 경계로 확장될 수 있다. 멀티윈도에서는 앱별 합계가 실제 경과 시간과 다를 수 있다.
- 통계 화면을 새로고침하면 현재 선택한 게임 목록으로 다시 가져온다. 권한이 꺼진 뒤에는 캐시가 표시될 수 있으므로 마지막 가져온 시각을 표시한다. OS 게임 기록으로 과거의 시간대별 이용을 추측하지 않는다.
- 웹·연결 구간은 v0.4 이후의 관측만 기록한다. 2초 간격 웹 관측 사이가 6초보다 길거나 시각 변화가 있으면 해당 구간을 적립하지 않는다. 같은 대상의 30초 내 차단 반복은 한 시도로 합친다. 차단 시도 횟수로 절약 시간을 추정하지 않는다.
- 화면상 비교는 최대 63일 범위를 조회한다. 로컬 DB에는 누적 기록을 유지한다. 날짜·시간대는 기기의 로컬 시간대 기준이다. 기기 시간대 변경 시 과거 구간의 표시 날짜가 달라질 수 있다.

## 프라임콩과 XP 수식

PrimeBean 별명과 물리·수학 취향을 반영한 Canvas 캐릭터다. 녹색 콩에 궤도·파동·ψ 노트·연구복·E=ℏω 수식을 연결했다. 0·50·150·400·1000 XP에서 5단계 성장하고 연구복·파동·양자 꾸미기를 해금한다. 캐릭터의 둥실거림·눈 깜박임·터치 인사가 있으며 터치 XP는 없다.

성장은 접근성 서비스가 연결되고 차단이 켜져 있으며 쇼츠 또는 선택 게임 차단이 설정된 관측 구간에만 적립된다. 공부량이나 실제 차단 성공률의 측정은 아니다. 서비스가 약 30초마다 기록하고 관측 사이가 90초보다 길면 소급 적립하지 않는다. 절전 상태에서는 일부 시간이 누락될 수 있다. 권한·차단을 꺼도 기존 XP는 차감하지 않는다. 내장 브라우저만 사용하더라도 이 버전의 성장 적립에는 접근성 연결이 필요하다.

수식의 x는 **해당 날짜의 누적 차단 연결 유지 분 ÷ 50**이다. 연속 세션 길이가 아니라 하루 누적을 사용하므로 세션을 나누어도 같은 수식의 보상이 증가하지 않는다.

기본은 F=50x. 나머지는 F=50[x+0.64g(x)] / [1+0.64g(1)]이며 다음 함수를 사용한다.

| 이름 | g(x) |
| --- | --- |
| 근호 | √(1+x)−1 |
| 로그 | ln(1+x) |
| 파동 | sin x |
| 가우스 | erf x |
| 쌍곡선 | asinh x |
| 감마 | lnΓ(1+x)/(1+x) |
| 누적 | ∫₀ˣ du/(1+u⁴) |

새 규칙은 수식 간 차이를 넓히되 하루 누적 시간 범위에서 최대·최소 비가 2배를 넘지 않게 검증한다. 선택 화면에는 수식과 기호 설명만 표시하며 예상 XP 표·미리보기 곡선·효율 순위를 표시하지 않는다. 캐릭터와 통계의 이미 획득한 XP 표시는 유지한다. 감마는 Lanczos log-gamma, 오차 함수는 수치 근사, 적분은 Simpson 적분을 사용한다. 근사 수식이므로 부동소수점 오차가 있을 수 있다.

오늘 첫 XP가 발생하면 그날 수식을 고정한다. 이후 선택은 다음 적립일에 적용되며 기존 XP는 재계산하지 않는다. 누적 보상은 이전 누적과 새 누적 함수값의 차이로 계산한다. 자정에 걸친 관측은 날짜별로 나눈다. v0.3까지의 성장치는 업데이트 시 누적 XP에 보존하지만 과거의 날짜별 내역을 만들어 넣지는 않는다.

## 권한·개인정보

INTERNET은 유튜브 WebView용이고, PACKAGE_USAGE_STATS는 선택 게임의 Android 사용 통계용이다. 접근성은 게임·웹 쇼츠 차단과 관측에 사용한다. 새 앱 실행과 인앱 링크 클릭을 받기 위해 이벤트 패키지 필터를 전체로 설정하며, 대부분의 앱은 패키지 확인 후 반환한다. 클릭 이벤트는 클릭 노드·조상 링크 메타데이터만 확인하고, 주소 탐색은 인식한 브라우저 및 카카오톡·네이버·Google 앱의 웹 호스트에 한정한다. 전체 URL·페이지 본문·영상 내용을 저장하거나 서버로 전송하지 않는다. 채널 ID·이름·사용자 분류, 이용 구간의 시간·범주, 선택 게임의 사용 집계, 차단 시도, XP를 기기 SQLite·SharedPreferences에 저장한다. YouTube 접속에 따르는 일반 웹 요청·사이트 캐시·쿠키는 존재한다.

통계 WebView는 앱이 만든 로컬 HTML과 집계 JSON만 사용하고 외부 네트워크를 차단하는 CSP를 적용한다. 외부 JS·분석 SDK·JavaScript native bridge·광고·결제를 추가하지 않았다. 삭제·데이터 삭제 시 로컬 기록이 사라지고 클라우드 복구는 없다. 루팅·유튜브 APK 수정·부트로더 조작·Knox 설정 변경은 없다.

## 0.5 수식 규칙 변경과 호환성

기존 규칙 ID 0~7은 그대로 보존한다. 새 규칙 ID 8~15는 같은 함수에 더 큰 가중치를 사용한다. 오늘 이미 적립한 growth 행은 기존 규칙 ID를 유지하고 다음 적립일의 수식 선택만 새 ID로 전환한다. 이 때문에 업데이트로 보유 XP나 오늘 이미 적립한 XP를 소급 변경하지 않는다. 통계의 실제 XP 그래프는 유지하며, 미래의 시간별 예상 보상은 표시하지 않는다.

검증: 0.01~1440분 구간에서 0.01분 간격의 1,152,000개 함수 평가를 수행해 유한성·단조 증가·동일 시간의 수식 간 최대/최소 비 2 이하를 확인했다. 기존 규칙의 결과와 분할 적립 합계도 검증했다. 이는 수치 그리드 검증이며 연속 구간 전체에 대한 엄밀한 수학적 증명은 아니다.


## 0.6 변경 이력 (이전 버전)

기존 이벤트 기반 차단 외에 약 2초 간격의 주기 점검에서도 쇼츠 차단을 실행한다. reportViewIds, includeNotImportantViews, retrieveInteractiveWindows를 요청하고 활성 브라우저 창에 한해 대체 루트를 확인한다. 주소창 ID 범위·양방향 텍스트 표시 문자 정규화를 보완했다. 추천 링크·일반 페이지 본문으로 쇼츠 여부를 판정하지 않는다. 사용자가 주소를 입력 중이면 이동을 방해하지 않는다. 당시에는 주소창이 전체 경로를 공개하지 않으면 차단하지 못했다. 0.7은 아래의 클릭 링크 감지와 잠금 중 제한 옵션을 추가했다.

홈의 접근성 연결 카드에 실제 서비스 연결, 주기 점검 시각, 마지막 주소 감지 결과와 이벤트·차단 동작 수를 표시한다. 상태는 메모리에만 유지하고 전체 주소나 페이지 본문은 추가 기록하지 않는다. 업데이트 후 접근성을 껐다 켜 새 설정을 다시 연결한다. Android 실행 중인 앱 목록은 포그라운드 서비스 표시이므로 이 목록에 표시되지 않아도 접근성 서비스가 실행될 수 있다. 실제 단말의 접근성 재연결·브라우저 호환성은 아직 미검증이다.


## 0.7 변경 이력 (이전 버전)

- 웨일·Firefox 파생 패키지, DuckDuckGo `omnibarTextInput`, 삼성 커스텀 탭 주소창 ID, Firefox 주소창 후보를 추가했다. 후보 등록은 최신 브라우저의 실기기 호환성 보장이 아니다.

- 이벤트·주기 점검·지연 이동 콜백의 RuntimeException을 복구하고, 주기 작업은 finally에서 다음 점검을 예약한다. 진단에는 복구한 오류의 종류와 횟수만 표시한다. 모든 크래시나 Android의 서비스 중단을 방지한다고 보장하지 않는다.

- YouTube 앱 활성 상태, 삼성 절전 예외·배터리 제한 없음 안내를 추가했다. 네이티브 YouTube 쇼츠 전체를 구분하는 기능은 없다. 접근성 해제·앱 데이터 삭제·재부팅 후 시각 조작 등 기존 한계는 유지한다.

기존 0.6 소스를 재빌드했을 때 첨부 APK의 classes.dex, AndroidManifest.xml, resources.arsc 해시가 모두 일치했다. 수정본은 동일한 앱 ID와 서명키, versionCode 7로 빌드한다. 기기에서 기존 앱 위에 업데이트할 수 있는 서명임을 인증서 비교로 검증한다. 소스 ZIP의 기존 개인용 베타 키는 업데이트 연속성을 위해 유지했다.

## 0.8 변경 이력 (이전 버전)

- 네이티브 YouTube는 쇼츠 차단이 켜진 집중 잠금 중 전체 이용을 제한한다. 잠금 밖에서는 표시된 `reel_recycler`, `reel_player_page_container`, `reel_watch_fragment_root`를 조회한다. BACK 후 850ms 뒤 같은 패키지·창에서 플레이어가 남을 때 HOME을 요청한다. 추천 선반은 플레이어로 취급하지 않는다. 유튜브 업데이트로 ID가 바뀌면 놓칠 수 있다. 시스템 YouTube도 목록에서 앱 전체 차단 대상으로 선택할 수 있다.
- `잠금 중 차단 해제 설정 가드`는 기본 켜짐이며 잠금 전에 변경한다. Android/Samsung 설정·패키지 설치기에서 보호 앱 이름과 삭제/강제 중지/사용 설정/접근성 스위치 증거가 함께 확인돼야 BACK을 요청한다. 일반 설정 목록에 이름만 나타나면 차단하지 않는다. 650ms 후 같은 창에 보호 화면이 남아 있을 때만 HOME을 요청한다. 전화·긴급 통화와 일반 설정은 대상이 아니다. 설정 UI/문구 변경·서비스 중단 시 가드를 놓칠 수 있다.
- 기존 잠금 최대 180분(선택 UI는 120분), 10분 조기 해제, 안전 모드 비상구를 유지한다. OS 앱 삭제 권한을 없애거나 루팅·기기 관리자 승격·Knox 변경을 하지 않는다. 같은 부팅에서는 경과 시간을 사용하지만 재부팅 후 실제 시각 복원의 기존 한계는 남는다.
- 웹 문서 루트의 URL을 별도로 보존한다. 루트에서 `https://m.youtube.com/`처럼 `/`가 명시되면 확인된 홈으로 처리한다. 주소창에 도메인만 나온 상황은 여전히 판별 불가다. 명시적인 현재 문서 URL이 이전 주소창 값을 가리지 않게 고쳤다.
- 카카오톡·네이버·Google·Instagram·Discord·에브리타임 웹 호스트는 미지원 브라우저 전체 제한에서 제외한다. 유튜브 경로가 불명확한 경우의 엄격 제한은 유지한다. 모든 인앱 브라우저·웹게임·릴스·틱톡·네이버 클립 지원을 뜻하지 않는다.
- 게임 목록에 `자동 감지됨`/`수동 선택`/YouTube `앱 전체 차단`을 표시한다. Android 게임 분류가 없는 앱은 직접 선택해야 한다.
- `잠금 후 새로 설치된 앱도 차단`은 기본 꺼짐이다. 잠금 시작 시 실행 가능한 앱의 패키지 목록과 잠금 식별자를 저장해 이후 새로 보이는 일반 앱을 제한한다. 시스템 앱·설정·전화·긴급 기능은 제외한다. 기준 목록 생성 실패 또는 이전 잠금의 기준이 없으면 추측 차단하지 않는다. 기존 앱이 새 실행 아이콘을 추가하면 새 앱으로 판단할 수 있다. 보안 폴더·다른 사용자 프로필은 관리하지 못한다.
- 팝업 가림막에 `최근 앱에서 닫기`를 추가했다. 게임 카드를 밀어 닫을 수 있도록 최근 앱 화면을 열고 게임 HOME 요청/가림막을 8초 동안 잠시 멈춘다. 그 후 다시 차단한다. 게임 프로세스를 강제 종료하는 기능은 아니다.
- `화면 view ID 수집 예약 · 30초`를 누른 후 대상 앱으로 이동하면 ID만 수집한다. 앱에서 선택·복사할 수 있으며 5분 뒤 지운다. 텍스트·설명·영상 제목·URL·extras는 덤프에서 제외하고 서버 전송이나 파일 저장을 하지 않는다. 명시적인 예약 중에만 실행하며 노드/ID 수 상한이 있다.
- 접근성 서비스의 차단 기록·주기 웹 구간·성장 기록은 단일 HandlerThread로 직렬화한다. 관측 시각을 메인 스레드에서 캡처해 큐 지연으로 시간이 늘지 않게 한다. 정리 시 앞선 기록을 마치고 작업 스레드를 종료한다. 통계 화면의 동기 읽기 자체를 모두 비동기화한 것은 아니다. 임의 앱 클릭의 조상 탐색은 줄이고 인식한 웹 호스트/브라우저 또는 명시적 targetUrl이 있는 클릭에 한정한다.
- 기존 서명 키를 유지하고 키가 없을 때 새 키를 자동 생성하던 빌드 동작을 제거했다. 0.7/0.8 인증서를 비교해 업데이트 연속성을 검증한다. 기존 앱 삭제·데이터 초기화 없이 업데이트한다.

추가 검증은 앱 플레이어·숨긴 노드·추천 선반 구분, 설정 목록 오차단 방지·보호 앱 정보·접근성 상세·삭제 확인·전화 패키지 제외, ID 덤프의 텍스트/주소 제외, 명시적 홈/도메인 축약 구분, 웹 호스트 예외와 새 앱 옵션의 정책 경계다. 기존 XP 1,152,000개 그리드·잠금·웹 가드·채널·통계 회귀 검증도 유지한다. API-35 컴파일과 APK 서명/정렬을 확인한다. 노드 검증은 JVM 대역 테스트이며 실제 One UI의 ID·문구·이벤트 시점·배터리·프레임 성능은 미검증이다.

업데이트 후 접근성을 껐다 켠다. 잠금 밖에서 유튜브 일반 영상/Shorts를 각각 확인하고 감지가 안 되면 수집 예약 → 해당 화면 방문 → 수집된 ID 보기를 사용한다. 짧은 잠금으로 앱 전체 제한, 설정 가드 대상/비대상, 팝업 최근 앱 닫기, 잠금 만료와 조기 해제를 확인한다.

## 0.9 변경 이력 (이전 버전)

- 삼성 접근성 `com.samsung.accessibility`와 디바이스 케어 `com.samsung.android.lool`, 구형 `com.samsung.android.sm`을 설정 가드·명시적 view ID 수집 대상으로 추가했다. 패키지 전체를 차단하지 않고, 보호 앱 이름과 관리 동작/서비스 스위치 증거를 함께 확인한다. 스위치 클래스도 보조 신호로 사용한다. 일반 설정·다른 앱 관리·전화·긴급 통화는 대상에서 제외한다. 실제 One UI의 ID/문구가 달라질 때 누락 가능성이 남는다.
- 설치기에서 집중콩 이름이 확인되면 버튼 문구가 `확인`이어도 가드 대상으로 본다. 잠금 중 자기 앱 설치/업데이트 확인에도 적용될 수 있으므로 아래 허용 창 또는 잠금이 끝난 뒤 진행한다.
- 삭제를 영구 금지하지 않는다. 앱의 `삭제 허용 요청 · 10분 대기`를 누르거나 집중콩 삭제 확인을 시도하면 대기를 시작한다. 10분 뒤 `삭제 진행 · 5분 허용`으로 앱 정보를 열거나 삭제 확인을 다시 시도하면 집중콩의 앱 정보/삭제 화면만 5분 동안 허용한다. 허용 창 자체는 집중 잠금·게임·쇼츠 설정을 해제하지 않는다. 앱 정보에서 강제 중지/데이터 삭제도 접근할 수 있으며 실제 삭제나 강제 중지 이후에는 서비스가 유지될 수 없다. YouTube 관리·접근성 서비스 해제 가드까지 함께 허용하지 않는다.
- 삭제 허용은 별도 경과 시간 타이머이며 같은 부팅에서 벽시계 변경으로 단축되지 않는다. 앱을 닫거나 다시 열어도 대기는 유지한다. 중복 요청으로 시간을 다시 시작하지 않는다. 허용 창 만료 후에는 새 대기가 필요하고, 새 집중 잠금에 이전 허용을 이어 쓰지 않는다. 재부팅하면 삭제 대기/허용을 다시 요청한다. 집중 잠금이 끝나거나 설정 가드가 꺼져 있으면 원래처럼 대기 없이 앱 정보를 열 수 있다. 기존 10분 조기 해제와 안전 모드 비상구는 유지한다.
- 최근 앱 정리는 원래 가림막이 표시된 패키지/창 ID에만 연결한다. 요청 버튼만으로 전체 앱 차단을 멈추지 않는다. 신뢰하는 런처/System UI의 실제 최근 앱 view ID가 활성 화면에서 확인됐을 때만 최대 8초간 대상 일반 게임 창 정리를 허용한다. 게임/차단 앱이 다시 활성화되거나 최근 앱을 벗어나거나 화면 정보를 못 읽으면 즉시 취소한다. 유튜브와 PiP 가림막에는 이 유예를 적용하지 않는다. 최근 앱 정리는 부팅 내 경과 시간 기준 2분에 한 번이고 쿨다운을 설정에 저장해 서비스 재연결에도 이어 쓴다. 최근 앱 화면 인식 실패 시 차단 유지 쪽으로 동작한다.
- 잠금 중 쇼츠 차단이 켜진 기본 YouTube 앱도 공통 차단 앱 판정에 포함했다. HOME 뒤 팝업·분할·PiP에 창이 남으면 기존 창 영역 가림막을 적용한다. PiP는 노드의 visible 플래그 외에 창의 PiP 상태를 함께 확인한다. 다른 앱·시스템 창이 위에 있는 부분은 기존 영역 계산으로 제외한다. 실제 삼성 PiP 창 트리·제어창 계층 호환성은 미검증이다. 앱 프로세스·소리를 강제 종료하는 기능은 아니다.
- 새 앱 옵션은 런처 아이콘 목록 대신 `PackageInfo.firstInstallTime`과 잠금 시작 실제 시각을 비교한다. 기존 아이콘 없는 앱/기존 앱 업데이트는 최초 설치 시간이 과거이므로 새 앱으로 취급하지 않는다. Android가 패키지 정보를 공개하지 않거나 이전 버전의 진행 중인 잠금에 시작 시각이 없으면 추측 차단하지 않는다. 기기 시각 조작·다른 사용자 프로필·보안 폴더 한계는 남는다.
- 동일한 앱 ID/서명 키를 유지하고 versionCode를 9로 올렸다. OS 설정·Knox·부트로더·기기 관리자 권한 변경은 없다.

추가 검증: 삼성 3개 패키지의 접근성/앱 관리 분류, `확인`만 있는 삭제 대화상자, 일반 설정·다른 앱·전화 제외, 실제 최근 앱 확인 전 차단 유지·재진입 즉시 취소·창/앱 범위·쿨다운·만료·PiP/YouTube 유예 제외, 설치 시각 경계, 삭제 대기 1ms 전/후·중복 요청·Activity 재생성·허용 창 만료·재부팅·새 잠금 범위를 검증한다. API-35 빌드·APK 서명/정렬과 기존 XP/잠금/웹 가드/채널/통계 회귀도 확인한다. 노드/타이머 테스트는 JVM Android 대역을 사용하므로 실제 One UI 동작을 증명하지 않는다.

실기기 확인: 새 빌드에서 삼성 접근성 서비스 상세/디바이스 케어를 ID 수집하고, 짧은 잠금에서 보호 화면·비대상 화면을 나누어 확인한다. 잠금 중 YouTube 팝업/PiP, 게임의 최근 앱 재진입, 2분 재사용 제한을 확인한다. 삭제는 요청 → 10분 대기 → 5분 허용 흐름으로 시험한다. 기존 앱을 지우지 말고 업데이트 설치하고, 접근성 재연결은 집중 잠금이 꺼진 상태에서 진행한다.


## 0.10 변경

최신 동작·R1~R9 상태·상수 후보·단계별 테스트·실기기 체크리스트는 동봉한 `REPORT-0.10.md`를 따른다. 자동 HOME/BACK은 실제 활성 패키지를 확인한다. PiP는 targeted dismiss와 재시도 제한을 사용하며 일반 앱에서 HOME 반복을 유발하지 않게 창별로 처리한다. 설정 가드는 순수 규칙으로 판정하고 전체 패키지 조회·새 설치 UUID 기록·바로가기 점검·네트워크 마감·조회 불가 프로필 옵션·YouTube 계열 5종·추가 진단을 포함한다.
